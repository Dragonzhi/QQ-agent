# 案屿 · 项目交接

项目根目录是本规范所在 `.agents/skills/isle/` 向上的三级目录。先读取该目录的 `TASKS.md`，以用户本次指定的项目和工作范围为准；不要把当前终端所在的子目录或其他项目当成目标。文件缺失、存在多份交接摘要或目标不明确时，先与用户确认，不重建或猜测覆盖。

本 Skill 只约定读取与回写项目记录，不授予实现、运行测试、提交、推送或调用其他 Agent 的额外权限。不要修改 Skill、项目规则或无关文件。

## 开工

- 读取完整 `TASKS.md`：状态、next、三个任务分节、交接摘要和工作留痕；必要时核对用户目标相关的工程状态。
- 用户本次目标和完成标准优先。列表首个进行中／待办只是参考，不等于已授权任务；未验证的旧结论仍需核实。不依赖上一家 Agent 的聊天记录。
- 目标不明确或只有等待事项时询问用户。按用户授权继续工作，结束或被要求交接时再执行收工。

## 收工回写

停止新增工作，只整理本次会话已经发生的结果。不要为补齐收工记录继续实现、补跑验证或提交代码。先重新读取文件，保留他人的改动，然后按顺序维护以下内容：

1. **任务清单**：维护 `## 待办`、`## 进行中`、`## 已完成`，缺少时才补上。未开始的具体行动用 `- [ ]` 放待办，已开始但未达标的放进行中；只有实际达到完成标准的任务才用 `- [x]` 并移到已完成。部分完成、阻塞、验证失败都保留未完成状态。本轮实际处理但尚未列出的工作应补入相应分节，明确的下一步行动进待办；已有相同任务则更新或移动原条目，保留标签和无关任务，不重复新增。纯讨论且没有行动项时可以不改任务，并说明原因。
2. **交接摘要**：在 `## 交接摘要` 合并本轮结果和仍有效的旧信息。记录已确认变更及必要路径、实际执行的验证与结果、未完成或阻塞、接手的第一个动作。没做的验证明确写“未验证”；不把尝试写成结论，不倾倒聊天记录。摘要不能替代任务清单。
3. **工作留痕**：向 `## 工作留痕` 末尾追加本轮贡献，保留历史。格式为 `- YYYY-MM-DD · 署名：实际推进的工作；任务状态；验证结果或未验证。` 同一天同一署名的多轮改动，追加合并到当天该署名那一条，写得简约，不堆叠多条；跨天或更换署名再起新条目。部分推进也记录；同一轮收工不重复追加，无新贡献时说明原因。署名采用用户本次指定的 Agent 名称；未指定时先确认，不猜模型名称。任务的 `@标签` 表示原计划接手方，不能据此推断实际作者或替别人补签。
4. **续接与日期**：next 写“停在哪里；下一步做什么”，updated 使用回写当天本地日期 `YYYY-MM-DD`。不凭首条任务猜测完成情况，不清空仍有效的信息。

二级分节标题固定，不追加日期、署名或说明；日期写元数据或留痕正文。已有 `## 交接摘要（YYYY-MM-DD）`、英文括号版本或带日期的工作留痕时维护原分节，不另建同名分节。多份摘要先确认如何合并，不按日期丢弃旧内容。摘要可用正文、列表、闭合代码块和 `###` 小标题。

保留原有编码、换行和无关内容。保存前再次核对读取后的文件是否被外部修改；有冲突先停止，不覆盖其他改动。保存后重新读取，核对任务、摘要、留痕和 next 是否一致。

回复说明任务清单的变更或不变原因、摘要及留痕记录了什么、实际验证与未验证内容、下一步，并在末尾使用同一署名。如果无法写文件，提供具体任务改动及可粘贴的摘要、留痕，不能声称已回写。
